# Maintaining this portfolio

This repo is read by recruiters and hiring managers. Keep it short, accurate and easy to scan.

## Layout

```
README.md                    Portfolio landing page: project table + skills matrix
projects/<name>/README.md    One page per project
projects/<name>/CHANGELOG.md Milestones, newest first
_template/                   Copy this folder for a new project
```

## Rules

1. **README = one page.** Sections: summary table, problem/what it does, architecture, highlights, skills, what's next. Up to 8 highlight bullets, each stating the problem *and* the result.
2. **CHANGELOG = milestones, not diaries.** One bullet per meaningful milestone, 1–2 sentences, grouped by month, newest first. Skip routine maintenance.
3. **Only claim what's running.** No planned features listed as done.
4. **Keep it public-safe.** No passwords, keys, tokens, IP addresses, hostnames, URLs of private services, serial numbers, customer data, employee names or sales figures.
5. **Update after each work session** that changes what a project does. Also update the project table in the root README when status or version changes.
